# อัปเดตงาน Backend — 22 กันยายน 2026

ขอบเขตงาน: Places / Admin / User ภายใน `pj-backend`
ปัจจุบันมีโค้ด API สถานที่และชุดข้อมูลแผนที่แล้ว ส่วน Admin / User ยังไม่ได้พัฒนา

## สถานะงาน

| ส่วน | ความคืบหน้า |
|---|---|
| Places | มี API อ่าน เพิ่ม แก้ไข ลบ และค้นหาตามชื่อ เลขห้อง หรือคำค้น กรองตามอาคาร ชั้น และ `place_type` |
| Place Keywords | มีตารางคำค้นและ API อ่าน เพิ่ม ลบคำค้นของสถานที่; ลบสถานที่แล้วคำค้นถูกลบตาม |
| ข้อมูลแผนที่ | เตรียมข้อมูลอาคาร 30 ปี ชั้น 4–7 รวม 78 สถานที่ พร้อมประเภทสถานที่; ห้อง 712 ยังไม่ยืนยันประเภท |
| นำเข้าข้อมูล | มีสคริปต์ดูตัวอย่างและนำเข้าโดยไม่ล้างข้อมูลเดิม เติม `place_type` เฉพาะรายการที่สคริปต์เคยสร้างและยังไม่มีค่า |
| Validation | ตรวจ UUID ข้อความ เลขชั้น และค่า `place_type` ก่อนใช้กับฐานข้อมูล |
| Bruno | มีชุด Map Verification 9 requests และคำขอทดสอบสร้าง แก้ไข กรอง และตรวจค่าประเภทสถานที่ |
| Admin / User | ยังไม่มีระบบบัญชี เข้าสู่ระบบ และตรวจสิทธิ์ |

## งานที่เพิ่มในรอบนี้

- ถอดชื่อและเลขห้องจากแผนที่ลง [building30.ts](../db/data/building30.ts)
- เพิ่ม [seed-maps.ts](../db/seed-maps.ts) สำหรับนำเข้าตามลำดับ อาคาร → ชั้น → สถานที่
- ปรับการตรวจเลขชั้นที่ใช้ร่วมกันใน Places และ Floors ให้ปฏิเสธค่าว่างและค่าที่เกินขอบเขตฐานข้อมูล
- เพิ่มชุด [Map Verification](../bruno/Map%20Verification) ค้นหา ID อาคารและสถานที่อัตโนมัติ
- เพิ่มคอมเมนต์ภาษาไทยสั้น ๆ ในไฟล์ข้อมูลและสคริปต์นำเข้า
- เพิ่มคอลัมน์ `places.place_type` และ migration ใน [db/migration](../db/migration) โดยอนุญาต `null` เมื่อไม่ทราบประเภท
- กำหนดค่าประเภทที่ API รับใน [place-types.ts](../db/place-types.ts) เช่น `classroom`, `laboratory`, `administrative_office`, `coworking_space`
- ปรับ [Places.route.ts](../src/routes/building/Places.route.ts) ให้รับ ส่ง และกรองตาม `place_type` และปรับ Bruno ให้ตรวจฟิลด์นี้
- เพิ่มตาราง `place_keywords`, migration และ API สำหรับจัดการคำค้น; `GET /places?search=` ค้นคำค้นได้ด้วย

## ผลตรวจและปัญหาที่พบ

- ตรวจ TypeScript ด้วย `tsc --noEmit` และ build ผ่านเมื่อวันที่ 22 กันยายน 2026
- ตรวจชุดข้อมูลแผนที่ได้ 78 รายการ โดยห้อง 712 เป็นรายการเดียวที่ `place_type` ยังเป็น `null`
- จากการทดสอบก่อนหน้า `GET /` ตอบ 200 แสดงว่า Backend เริ่มทำงานได้
- เคยพบ API ตอบ 500 เพราะเชื่อม PostgreSQL ไม่ได้ (`ECONNREFUSED`) ขณะ Docker ยังไม่ทำงาน
- ตรวจฐานข้อมูล `mydb` แล้ว migration ผ่าน และนำเข้าได้ 1 อาคาร 4 ชั้น 78 สถานที่; `/health/database` ตอบ 200
- ทดลอง API คำค้นบน localhost โดยเพิ่ม ค้นหา และลบคำค้นชั่วคราวสำเร็จ; ยังไม่ได้รันชุด Bruno ทั้งหมด

## วิธีตรวจงานต่อ

รันใน `pj-backend` ทีละคำสั่ง โดยให้ PostgreSQL พร้อมก่อน migrate:

```bash
docker compose up -d postgres
docker compose ps
pnpm run db:migrate
pnpm seed:maps --apply
pnpm dev
```

ถ้าคำสั่งใดผิดพลาด ให้ตรวจสาเหตุก่อนทำขั้นถัดไป
ใช้ `seed:maps --apply` สำหรับข้อมูลแผนที่; `pnpm seed` เดิมล้างข้อมูลและใส่ตัวอย่าง

ใน Bruno เลือก collection ของ `pj-backend/bruno` และ environment `Local`
รันเฉพาะ Map Verification ตามลำดับ 01–09: รายการ 01–08 ควรได้ 200 ส่วน 09 ควรได้ 400 และ Tests ผ่าน
ในโฟลเดอร์ Places มี `Filter Places By Type` (คาดหวัง 200) และ `Invalid Place Type` (คาดหวัง 400)
ส่วน `Create Place` และ `Update Place` เป็นคำขอที่เขียนข้อมูล ใช้กับฐานข้อมูลทดสอบเท่านั้น
หากจะทดสอบคำค้น ให้รัน Map Verification ก่อน แล้วรัน Place Keywords ตามลำดับ 01–04
ชุดนี้เพิ่มและลบคำค้นทดสอบหนึ่งรายการ

ตัวอย่างค้นหาห้อง 701:

```http
GET {{baseUrl}}/places?floor=7&search=701
```
